Wiretap is a security-first network debugger for Windows 10 and 11. Every app's connections appear live with the process that made them; HTTP and HTTPS are recorded in full, bodies included; WebSocket, Server-Sent Events and gRPC are decoded message by message. Its own desktop app, written in Rust, with a small kernel driver.

What it does

The goal is one tool that combines what HTTP Debugger Pro, Fiddler, mitmproxy and Wireshark do, on a small, tested core.

Every app, every connection

Start a capture and every TCP and UDP connection of every app appears live with its process. HTTP and HTTPS are sent through Wiretap's local proxy automatically: no proxy settings, nothing to configure per app.

HTTPS, with your consent

Decryption is opt-in: Windows itself asks you to trust a per-user Wiretap root, whose key cannot be exported. Servers are verified like a browser would; anything Wiretap cannot verify is passed through untouched.

HTTP/1.1 and HTTP/2

Every request its own row: method, URL, headers, bodies, timing. Keep-alive and pipelining; HTTP/2 streams, HPACK, trailers and server push, relayed frame for frame. gzip, deflate, Brotli and Zstandard bodies shown decoded.

WebSocket, SSE and gRPC

A live Messages tab, like browser developer tools: WebSocket messages (with permessage-deflate), Server-Sent Events as they arrive, gRPC and gRPC-Web messages shown as Protocol Buffers, and the call status (failed calls show gRPC 5).

Rules

Auto-reply (Wiretap answers, the server is never contacted) or redirect to another server, over HTTP/1.x and HTTP/2. Create one from any captured request; templates such as {{request.path}}; share groups as .wtrr files.

Never breaks traffic

Apps that pin their certificates, Windows services and apps that refuse the Wiretap certificate are relayed untouched, with their clear-text TLS details still shown. No idle limits: WebSockets and streams live as long as their endpoints, even after the capture stops.

Search that knows your traffic

Field filters such as host:, app:, status:4xx, type: and - to exclude, with auto-complete from what you captured.

Sessions and HAR

Every capture is stored in a local SQLite database with a quota and tamper detection. HAR 1.2 import and export, WebSocket messages included.

How it works

A small kernel driver does as little as possible; everything that parses traffic runs in user mode, in memory-safe Rust.

Your appsEdge, services, any program: nothing to configure.
WiretapDriverWindows Filtering Platform callouts: sees each connection and its process; while capturing, sends TCP 80/443 to the proxy.
Wiretap proxyDecrypts (if allowed), decodes HTTP/1, HTTP/2, WebSocket, SSE and gRPC, applies rules, then talks to the real server.
The appLive lists, request details, Messages tab, rules, sessions. Stored in SQLite.

Privilege split

The app runs as you. Only capturing asks for administrator rights (it loads the driver and installs its filters). The driver parses nothing it receives from user mode beyond one fixed-size, validated setting.

One language-neutral model

Every event and flow serializes to one stable JSON shape (snake_case, UUIDs, microsecond timestamps), the contract future SDKs will build on: Python first, then .NET, C++, Rust and Go.

Security by design

A debugger that sees decrypted traffic must not become a weakness itself. The full analysis is in the threat model.

A small, safe driver

  • Redirects only TCP 80/443 to Wiretap's own proxy, and blocks QUIC while capturing; never modifies or injects data; fails open on any error.
  • One device, SYSTEM and Administrators only, three IOCTLs; no memory, process, file, registry or token operations.
  • No panic path in the release build (checked at link time); never unloads under connections it redirected.

Honest, bounded parsing

  • Every parser is bounded, panic-free, tested against official vectors and fuzzed (21 fuzz targets, replayed on every build).
  • Encrypted traffic is never labelled as decrypted; the data model rejects it.
  • Captured data cannot inject into the UI, HTTP or terminals.

Your keys, your consent

  • The Wiretap root is per user, its key non-exportable, trusted only through Windows' own dialog, and deleted when you turn decryption off.
  • The UI is served on loopback only, behind a per-run token, with strict origin checks and a strict content policy.

Small supply chain

  • Four runtime dependencies, all on their newest versions, checked by cargo deny and cargo audit; locked builds.
  • Windows' own TLS stack (SChannel) and key storage (CNG); the WebView2 loader pinned by version and SHA-512.

Requirements

Step-by-step instructions are in the setup guide.

Windows

Windows 10 22H2 or Enterprise LTSC 2021, Windows 11 24H2 or 25H2; x64 client editions. Windows Server and ARM64 are not supported.

Rights

An administrator account: the app runs as you, and only capturing asks for elevation.

Driver signing

Release packages will carry a Microsoft-signed driver and install with Secure Boot and Memory Integrity on. v0.2 is built as a test package, for lab machines and VMs only.

There is no public release yet. Wiretap is tested by hand on Windows 11 build 22621 in a VM; Windows 10 and newer Windows 11 builds are not yet tested.

About this project

Wiretap is a vibecoded, human-guided experiment: how far can AI help build a Windows network debugger, kernel driver included, when a person sets the direction and reviews the work? It is intentionally kept simple for learning and experimentation and is not designed to become a product.

Development is published in gradual research checkpoints. Each one adds a limited set of capabilities, documents what was tested and what remains open, so you can follow and judge the progress over time. Most of the code, tests and documentation are written by an AI coding assistant (Claude, by Anthropic) from requirements the maintainer sets; the maintainer directs, reviews and tests on real Windows. AI-written code can be confidently wrong, so Wiretap relies on machinery rather than trust: strict lints, tests for every rule, fuzzing of every parser, layout checks of every kernel binding, supply-chain checks, and no claim of support without a test.
